# dotagents

Source repo for agent customizations (skills, rules, global AGENTS.md). Primary harness is pi.

## What is live

pi reads these paths directly. Edits take effect on the next session or `/reload`:

- `~/AGENTS.md` → `GLOBAL_AGENTS.md` (symlink)
- `~/.agents/skills/` (pi skill discovery)
- `~/.agents/rules/` (pi-rules extension)

Nothing needs an install step.

## Layout

- `GLOBAL_AGENTS.md` — the LIVE global instructions file
- `skills/` — agent skills, one flat directory each (`git-commit/`, `pr-review/`). User-invoked-only skills carry `disable-model-invocation: true` and `user-invocable: true` in `SKILL.md` frontmatter
- `.agents/skills/` — repo-local skills (`publish/`, `update-dependencies/`, `convert-to-gemini-command/`). pi loads them only when `cwd` is this repo. They maintain this repo and are not meant for other projects
- `rules/` — path-scoped rules; YAML frontmatter `paths:` globs control activation, no frontmatter = always loaded
- `gemini-commands/` — Gemini CLI equivalents, regenerated from `skills/` via `/convert-to-gemini-command`
- `store/catalog.json` — machine-readable catalog, regenerated by `/publish`
- `hooks/`, `claude-statusline/`, `claude-output-styles/`, `helpers/` — legacy Claude Code artifacts, kept as-is, not used by pi

## Workflow

- After adding/renaming a skill, run `/publish` — it regenerates `store/catalog.json`, `dependency.md`, and the README, then commits and pushes
- New external tool requirements go in `dependency.md` (`/update-dependencies` scans for them)
- Rule files: one gotcha per bullet, earned from real incidents — not generic advice
